## 3. 怎样把 UI 改得清楚、协调

先分区，再放文字。首页先安排品牌区、标题/通信状态、电压与信号、主读数、初锚力、右侧信息卡；菜单先安排侧栏、标题、参数行和底部操作。让重要数字获得最大的有效空间，装饰线避开字、数字、单位和边框，不为增加科技感牺牲可读性。

固定标签与动态数字分开处理。首页的“通道”“初锚力”等文字有一部分在背景位图中，只改 `UI_Main_Display` 不会改变这些字。固定标签改生成器并重新生成，动态数字改格式化或绘图辅助函数。不要把参考图片的样例数值一起裁进背景。

字号相同不代表看着一样大。字模有上下留白，数字和汉字也不同。`Home_CenteredText` 根据亮点范围居中，`Home_AsciiOffset` 修正混排位置。状态行目前对 16 px 汉字生成统一 14×14 可见字框；这是该状态行的专用处理，不必强制拉伸所有中文。商标中文字采用 `SIMLI.TTF` 隶书，首页一般中文采用 `simhei.ttf`，单位/部分静态英文采用 `arialbd.ttf`；保留具体设计要求。`UI_Text` 用基线坐标，`Home_Text` 与 `Ref_Text` 用左上角坐标，不能直接互换同一个 y。

小字号要以目标像素评价。当前生成器对部分黑体先放大栅格化再降采样，阈值决定哪些灰阶边缘变成墨点。调阈值时同时看断笔和字腔，强制膨胀可能把“机”“通”等字糊成块。普通文字不宜靠横向压缩硬塞进区域；优先调整区域宽度、间距、字号层次。Logo 图形和低像素图标可以单独裁切或重画。

数字优先，标签随后。当前双通道首页初锚力数字区域宽 **50 px**，`Home_InitialText` 按实际字符串宽度选择 **28→22→18→16 px**。因此扩大标签却挤窄数值区域，会令真实读数退到更小字号。检查普通读数和最长合法读数，也检查小数点、冒号、单位间距。`99999.9` 可以作为独立字符串的排版压力样例，但不代表当前 `uint16_t` 协议可以传输这个值。

最后同时看 1 倍与整数倍预览。1 倍看可读性和层次；3 倍最近邻看像素、基线和间距。越界检查通过只说明没出屏幕，仍可能发生内部重叠、数字挤单位或边框穿字。

## 4. 必须保留的当前语义

- 首页和安装调试的通道一/二取 `UI_main.data[0/1]`；首页初锚力和初锚力参数页取 `Menu_rank7.initial_force[0/1]`。当前实时通道按 `/10` 显示整数，初锚力按 `/10` 和 `%10` 显示一位小数。参考图不能替换这些数据来源。
- `UI_ChannelCount` 接受现有单/双通道选择，其他值回退到 `ui_home_config.h` 的默认值，当前默认 1。隐藏 B 不清空 B 数据，不改变接收参数数量。
- 当前标定是 **000/150/300 KN** 三点、两列 AD；每个 `OK` 由该点成功标记决定。单双通道均显示两路 AD。焦点 **0/1/2** 是三个标定点，**3** 保存并重启，**4** 返回不保存。函数上方旧注释仍写“两处标定点”，应以实际循环和调用为准。
- 初锚力值与 AD 为只读显示；现有按钮 **2** 为重置、**3** 为返回。显示端呈现外部主控焦点及下发结果，不因绘图函数被称为 `Control` 就把它理解成执行物理标定或传感器重置。
- 密码、组网结果、已存/新地址、保存提示和返回提示有各自分支。参考图出现的新按钮，不自动授权添加操作或改变编号。

局部重绘也是布局的一部分。安装调试的 `Install_RememberFrame`、`Install_UpdateFrame` 和 `Install_ToggleFocus` 保存数据、清除数值区域并恢复焦点。页面、等级或通道数变化会使缓存不能复用。改变行位置、数字区域、字体高度或按钮位置时，要核对完整重绘与局部更新是否一致，否则首次进入正确、下一次刷新就可能擦错位置或留下旧字。

## 5. 生成资源时容易遗漏的事

- 当前位图用 `u8g2_DrawXBMP`：按行保存，每行 `ceil(width/8)` 字节，字节内低位对应左侧像素；宽度不是 8 的倍数时保留行末填充。
- 绘图颜色、透明位图模式、焦点 XOR 和发送反相各有作用，修改后恢复其状态。`UI_SendBuffer` 发送前异或、发送后恢复缓冲，不能遗漏恢复步骤。
- 字模已经使用只读字节池和 `*_at(index)` 取址宏。资源生成器接入 `pack_ui_fonts.py`，不要重新生成成旧数组形式却仍沿用新取址接口。
- 首页 `home_codes` 是显式字符集合；新增状态文字必须补足字库。侧栏生成器从当前页面及参考绘图头文件提取中文，仍要查看字符覆盖和字号。
- 输出先放本项目，检查脚本是否覆盖正式资源、预览或历史证据。备份放到不会参与编译的目录；确认工程源排除配置，不把 `before` 下的 C 文件编进固件。

## 7. 修改后的最短验证流程

先确认生成器和编译目标确实包含修改。构建用显式 `all`；本工程先 include 依赖文件，默认 `make` 可能只检查启动对象而没有链接新固件。当前本机工具路径已经确认存在：

```powershell
Set-Location -LiteralPath 'D:\y\初锚力'
$uiMake = 'D:\11\MounRiver_Studio2\resources\app\resources\win32\others\Build_Tools\Make\bin\make.exe'
$uiGccBin = 'D:\11\MounRiver_Studio2\resources\app\resources\win32\components\WCH\Toolchain\RISC-V Embedded GCC12\bin'
$uiSavedPath = $env:Path
try {
    $env:Path = "$uiGccBin;$(Split-Path -Parent $uiMake);$uiSavedPath"
    & $uiMake -C obj all -j4
    if ($LASTEXITCODE -ne 0) { throw '固件构建失败，检查完整输出' }
} finally {
    $env:Path = $uiSavedPath
}
```

需要排除旧对象影响、验证生成配置或作存储前后比较时，使用 `-B` 强制重编译；不把每次小改都扩大成全量清理。产物是 `obj/CH584M_TFT_HB.hex`、`.elf`、`.map`，检查真正的链接结果、警告、FLASH/RAM 和源文件范围。

相关桌面回归入口：

```powershell
python tools/verify_initial_force.py
```

该脚本默认生成的六张预览没有传通道参数，按当前默认单通道输出。内部回归包含双通道，不等于六张图可用于评价双通道放大效果。运行后生成的 `render.exe` 接受“等级、菜单、焦点、样例、输出路径、通道数”，局部需求可显式生成相关页面。例如双通道首页普通值与合法极值：

```powershell
& '.\obj\initial_force_check\render.exe' 1 0 0 1 'obj/initial_force_check/dual_home_normal.pgm' 2
& '.\obj\initial_force_check\render.exe' 1 0 0 99 'obj/initial_force_check/dual_home_limits.pgm' 2
```

这些 PGM 是原始缓冲位值；首页最终预览需要按导出器的 `ImageOps.invert` 映射为白底黑字，菜单不做同样的导出反色。复核发送路径后检查实际图片配色。

需要完整页面交付时，再按需运行 `python tools/export_page_images.py`；它会覆盖已有页面输出及 ZIP，局部排版修改不必默认全量导出。这两个 Python 入口需要 Pillow 及本机 MSVC 初始化入口 `D:\visual studio\visual studio2026\VC\Auxiliary\Build\vcvars64.bat`；初始化文件本轮已确认存在，未重新验证编译器运行。

按改动风险选择状态：单/双通道、普通值/最长合法值、长中文状态、密码/成功分支、二级浏览/三级焦点、进入页面/连续更新/切回页面。模式变化检查 1→2→1，比较缓存更新与完整重绘，确认隐藏 B 更新不会串入 A。公共绘图改动再扩大到共享页面；检查绘图前后 `data_LIST` 未被改写、无关模块和用户修改未被覆盖。

最后核对差异及资源再生成一致性。不要用上一轮的“1283 项通过”或某个旧固件尺寸填本轮报告，测试数量以实际运行输出为准。
