# 跨项目的单色屏 UI 修改经验

这些方法来自 CH584/u8g2 UI 修改中的具体反馈。字体源、阈值、坐标、配色、协议和工具链须随当前工程确定；具体证据见 [初锚力案例](chumaoli-case.md) 和 [蓝牙显示案例](bluetooth-display-case.md)，仅在需要时阅读。

## 先解决“改了却没变化”

确认用户指的是固件屏幕还是电脑上位机。工程可能有原版、修改版、备份和重复文件；从实际编译配置确认参与构建的源文件、头文件、背景资源。静态背景的标签不会因为移动动态数值函数而改变。

把需要修改的元素分成静态背景/图标、动态文字/数字、选中态、局部更新区域，找到各自入口后做最小修改。资源生成器、头文件和实际编译必须形成一致结果。文件名叫“当前代码”、HEX 时间较新，或目录里已有 PNG，都不足以单独证明本轮修改已进入目标。

`u8g2_SetFont` 可能只保留绘图上下文，页面实际用自定义字模表和 `DrawXBMP` 输出文字。沿文字辅助函数查到字体资源、尺寸参数和宽度计算，不按附近注释判断实际字体。二分查字要求字符表有序；多个字号共用查找上界时，还要确认各表字符集合及数量一致，缺字回退为 `?` 不能当作完整覆盖。

## 给读数安排空间

先划出重要数字、单位和可变内容的区域，再确定标签和装饰。用户要求“标签和数字都更大”时，先看有没有足够空间；标签增大可能令数值区变窄，使自动字号反而降级。

测量实际使用的字模和 advance，按最长合法字符串预留：最大/最小值、符号、小数点、单位、最长地址、最长状态。以当前数据类型、协议和格式化结果为边界；额外的长字符串可以用于排版压力检查，不能据此改变协议或数值类型。

可以调整分区、标签位置或行数，并采用少量字号层次。先看整体信息优先级和用户指定风格，避免所有元素一起放大。单位位置应稳定，数值不能越过相邻区域；“未越界”检查还要配合内部碰撞和可读性检查。

检查坐标从常量、临时变量到绘图参数的完整类型链。屏宽超过 255 时，即使接口是 16 位，8 位临时变量也可能先截断右栏坐标。右对齐减法先在有符号空间检查剩余宽度，再转换为绘图坐标；不要让过长文字的负起点回绕成大正数。

可变 BLE 名称先拷贝到有终止符的本地缓冲，按真实字模宽度选择字号和字符边界截断，不改写绑定表或直接截断 UTF-8 多字节字符。这只解决已有合法编码的排版；异常/截断编码是否被拒绝或替换仍需核对实际解码器。末行要包括 `g/j/p/q/y` 等下伸笔画，不能只检查数字和大写字母。

## 视觉居中与坐标约定

字模画布可能含较多留白，“按字号居中”和“按墨迹居中”不是同一位置。混排 `2号`、英文、数字和中文时，先看实际可见上下沿。参考案例曾出现数字偏高、状态行中的“正”偏低、Logo 英文偏离中心。

假设整组文字在绘图原点下的可见边界为 `[x0,x1) × [y0,y1)`，目标矩形为 `(left,top,width,height)`。对于以左上角为原点的绘制接口，可用：

```text
draw_x = left + (width  - (x1 - x0)) / 2 - x0
draw_y = top  + (height - (y1 - y0)) / 2 - y0
```

采用整数坐标时再处理一像素的取整或光学校正。若文字宽度超过目标区域，先处理布局或字号；C 中注意有符号运算，不能让负差值在无符号宽度计算中回绕。

很多字体 API 的 y 是基线，位图 API 的 y 是左上角。换接口或抽取字模时先明确坐标语义。字符串尽量共用基线，不对每个字符独立顶对齐。专用状态行需要统一可见字高时可以单独处理；不要把小数点、下伸字母或所有中文都强行拉成相同字框。

## 小字清晰度

单色屏最终只有墨点与背景。抗锯齿灰阶如何二值化，决定细笔画会消失还是字腔会堵住。案例中小字号黑体的内嵌点阵与分别裁字，曾导致发白、断笔和高低不齐。

按目标像素试用字体，需要时先以较高分辨率离线栅格化、降采样，再调整阈值。一次只改变必要条件，比较普通文字和难辨字符。不要把某次采用的字体或阈值变成所有项目默认值。

整体膨胀能增加墨量，也会堵住字腔、让相邻笔画粘连。优先看当前字体源、阈值和像素分布；局部修整要有具体问题依据。普通标签不要靠大幅横向压缩塞进窄栏，优先调整留白、区域和字号。

新增状态或按钮文字时，确认字库包含全部字符和需要的字号。不同字号可能来自不同表；修改字体生成器后，核对生成结果确实被本轮头文件及绘图访问器使用。

同一 `DrawColor` 的纯黑白字模也会因墨点密度显得深浅不同，不能据此引入灰度或宣称电气黑度已修复。密集汉字可比较同字体原尺寸单色 hinting 与高倍栅格降采样。用户要求同字体时，不为一个难辨字悄悄换另一字体；若局部增强，基于未修改点阵判断窄字腔，避免整圈/竖向膨胀堵住一像素间隙，同时核对字宽、基线和普通/选中态。原尺寸与形态学方案只在当前字符、字号和反馈下选择，不成为全字库默认处理。

笔画粘连时不要沿用“发白就加粗”的方案。保留字体、advance、画布和基线，可只为问题字符选择原尺寸单色 hinting；共享字模会影响其他使用该字的页面，一并查看。按数组比较目标字模、索引和尺寸，确认影响范围；依赖不齐时使用已有兼容生成环境，不为文档总结重新生成资源。

专用标语/品牌位图可与正文表采用不同尺寸，但生成宽高、advance、基线、绘图与检查器应对应。普通值保持目标居中，最长版本号等邻近动态内容触发预先定义的防碰撞规则；不要为极端输入把所有普通画面永久挤偏。字体环境与依赖版本影响产物，生成后比较目标数组和其他数组，重复生成确认一致性。

## 图标、品牌和装饰

低像素图标先保留有识别意义的轮廓。参考案例的 Wi-Fi 图形需要三道弧线、圆点和明显间隔；删掉一条弧线虽可能更清晰，却没有满足用户参考。数量、方向、线宽及元素间的空白都要核对，不能只凭“看着像”交付。

商标图形可以单独裁切和缩放，品牌字体按用户素材保留。动态状态和读数独立绘制，不能将参考图中的示例值裁进背景。图形像 Wi-Fi 也不表示可以新增 Wi-Fi 通信功能。

斜体字标的字母横向边界可能重叠，按空白列切分会合并字母。需要逐字调整时可离线分析连通笔画，再按素材关系组合字身、点和下伸笔画；连通块数量、滤噪阈值和裁切坐标不能照搬到另一商标。

边框、切角、斜纹和分隔线应该帮助组织信息。检查文字/单位与边框的间距、两翼装饰的对称关系、按钮文字留白；装饰不能穿过读数、和字符笔画粘成一团。

## 黑白极性与帧缓冲

依次核对缓冲中 0/1 的意义、绘图颜色、位图透明模式、发送前反相、显示控制器设置和预览导出映射。首页与菜单可能采取不同的发送方式，不能因为首页需要白底黑字就反相全部页面。

部分发送函数会临时 XOR 整个缓冲，再在发送后恢复。遗漏恢复会破坏缓存和后续绘制；焦点 XOR 也可能需要先撤销旧焦点再画新值。预览工具读取的是发送前、发送中还是恢复后的缓冲，应明确说明。

u8g2 的 XBMP 通常是逐行保存、每行 `ceil(width/8)` 字节、字节内低位优先。实际内部帧缓冲则可能按竖向八像素组织，不能直接混用。非 u8g2 工程先检查自己的位序、步长、方向和裁剪规则。

## 上电画面与运行中重初始化

用户说“替换上电瞬间画面”时，先区分控制器初始化、上电首帧、主控页面指令和普通主页。搜索初始化的全部调用者，追到任务中的延后执行、开屏/息屏命令与首帧 RAM 写入顺序；把图放进正常页面或保持息屏等待主控唤醒，会改变用户要求的显示阶段。共用初始化函数还可能在主页出现后再次调用，启动品牌图应按授权的生命周期显示，保留真实的运行中重初始化需求。

实际绘图预览正确不代表初始化时序正确。验证首次调用、后续调用和完整复位后再调用；核对完整图像先于开屏发送、RAM 位序/旋转、DMA 暂存与新增延时。保留现有息屏策略，不用无条件常亮或停留延时掩盖画面出现时机。具体案例、已撤回方案与实屏待验项见 [启动初始化踩坑记录](startup-initialization-case.md)。

桌面预览、备份目录即使不在旧 Makefile 中，也可能被 IDE 自动扫描。生成含 `main`、主机库调用的 C 文件前，将目录从当前所有固件构建配置中排除；同时核对 IDE 再生成后的源集合和实际链接对象，随源码包交付持久的排除配置。不要只修生成的 Makefile，也不要把桌面测试 `main` 改名或伪造主机 API 来让其混入固件。

## 连续更新与焦点

完整重绘正确不代表更新路径正确。移动或放大数字后，旧清除矩形可能擦不完整；改标签却继续复用旧缓存，可能在第二次刷新留下重叠。核对值区域、背景恢复、透明模式、旧焦点撤销和新焦点绘制。

缓存有效性可能受页面、等级、焦点、通道数量、布局模式、数据及字体影响，沿当前项目的已有机制处理。模式切换要检查往返重复切换；某通道被隐藏时，更新其数据不应改变另一通道画面，也不应清空被隐藏的数据。

密码、标定成功、组网结果、保存提示和返回提示常有独立分支。按钮位置改变要保留原编号，值只读时不要为追求参考图效果新增编辑焦点或实际硬件动作。

## 菜单可达性与命令边界

菜单绘图回调存在，仍可能被串口最低参数表或菜单范围拒绝；旧页面留下会伪装成“UI 没更新”。从帧解析、校验、状态写入到活动路由逐层定位，不能只扩大渲染数组。子页标志可能在切换后残留，判断需同时包含页面等级、所属菜单和子页标志；覆盖跨菜单残留标志、合法最短帧及拒绝帧无副作用。

显示端删掉按钮、改成“保存并返回”或画出确认框，不表示外部主控的焦点循环、命令执行及返回时机已修改。缺少主控代码时交付具体需要联调的索引/分支，不宣称按键已受限，也不自动限制协议来掩盖问题。绘图保持只读；若本工程已有或用户授权了命令层状态转移，则检查完整路径，不将“纯渲染端”误当成禁止合法本地返回。保存结果应答、成功/空表/失败提示、扫描模式、息屏计时及后续主控旧帧覆盖分别核对。

本地返回被覆盖与子页残留标志是不同路径：前者来自后续完整页面快照，后者来自绘图路由条件。复现应覆盖同一次 UART 消费内的保存与旧页帧、提示结束后的周期旧帧，并使用真实提示倒计时；只画返回状态或用提示桩不能证明稳定返回。确需返回保护时定义设置、保留与合法解除条件，继续缓存业务参数，检查扫描/息屏副作用。协议无页面序号时，相同旧帧与再次进入无法区分，需主控发送父页或其他合法页面确认，不能靠固定延时猜测。显示保护也不替代主控按键状态和发送队列同步。

## 元数据、等待值与展示集合

绑定表可能先知道通道类型、名称和单位，实时缓存随后才收到测量值。分别检查未绑定、已绑定但未收值、收到真实零值、部分通道收到值，不能用 `value == 0` 判断无数据。有效标志还可能表示分配、已接收或新鲜度，按写入和清除位置确认语义，不把“收到过”当成“当前在线”。

一台设备可能映射多个不同量纲的子通道，不能把设备级类型复制到所有通道。按绑定起点、通道数量及实际解析规则解析显示类型；类型用于名称/单位表索引前检查枚举范围，绑定区间须与当前缓存容量一致。格式化时局部处理有符号值和标度，不改写原始数据或通信包。单位未定义时留空，不凭标签猜测。

首页分页和名称/RSSI/电压列表不必共用展示集合。用户授权改成同屏时，可让旧页码在该列表中呈现相同内容，但绘图不能顺手清零主控页码、重排通道、模拟确认键或改变退出操作。用独立的首尾/跨列通道数据、旧页码和进入→切换→退出→重入序列核对映射，避免全部相同样例掩盖重复或漏项。仅分配在不同列的常量也可能共用，修改前搜索引用。

“扫描到”与“成功绑定”的清单不是同一来源。短扫描缓存替换不应让已绑定记录消失，未绑定候选也不应计入绑定数。数组容量、正常设备数、占用通道数和异常恢复记录分别计算；溢出时显示全部、防御布局或截取部分由当前需求决定，总数与可见数的差异要明确。奇偶数量覆盖列平衡，取消轮显还要跨多个旧轮显时刻检查画面稳定。

先明确列表是均衡分列还是固定编号区间；两者同为双列，少量数据的位置却不同。固定每列 K 行时用零基索引 `column=index/K`、`row=index%K`，明确适用容量，另保留异常记录策略。重点验证 K、K+1、满表的唯一编号与名称对应，并同步真实布局检查器；隐藏 MAC 只修改展示，不清除绑定标识，历史保留完整 MAC 的策略不成为所有页面的要求。

对于需求仍要求展示完整 MAC/地址的页面，即使字符数固定也未必等宽。测量真实 HEX 字模，先保留完整标识、序号和间隔，再把剩余宽度分配给名称；覆盖最宽字符组合与长名称，按字符边界裁剪本地副本。不要用“12字符×假定字宽”替代实际测量，不为保留同屏而悄悄省略设备标识。

## 异步更新与重绘预算

无线状态先追踪发送端取值、UART 参数位置、缓存和资源索引：名称叫 RSSI 的字段可能已经编码成档位，图形像 Wi-Fi 也可能表示 LoRa。接收端不要重复分档或照搬旧枚举。只有 HEX 时校验记录、说明分析版本，并区分反汇编可证明的编码与用户确认的图形顺序；不能推断 dBm、联网或断线。协议版本数字与产品前缀同样分开核对，不从外观需求推导新协议含义。

BLE 回调更新缓存、UART 更新页面、TMOS 消费绘图请求时，检查两个数据源是否都能触发有效重画。纯布局修改沿用当前完整重绘或局部更新方式，不为套用历史缓存经验引入新机制。

若频繁收帧会拖慢通信，沿真实路径检查全屏发送、显示初始化和延时是否阻塞。已有事件架构中可合并重画请求、按最小间隔消费，保留等待期间的新请求；耗时初始化通常需要单独合并和延后。速率、tick 单位及回绕运算以本工程 SDK 和代码为准，注释中的 SPI 时间和占用率估算需要测量才能成为性能结论。视觉预览不验证事件时序或 BLE 实际响应。

息屏/休眠门控与绘图分开检查：关闭显示时避免继续发送整屏，唤醒时绘制最新数据，后台接收是否继续按已有业务要求保留。若只改 UI，发现调度条件异常先记录证据和范围，不能把疑似错误行为提炼成推荐做法。

## 资源与验证工具的复用边界

只用自定义 XBMP 字模的页面，残留 `SetFont` 仍可能让未使用的大字库被链接。优化占用前搜索实际活动文本调用和字体状态读取，以 map/nm 与链接器段占用验证保留原因；确认初始化和后续绘图不依赖字体上下文后再移除无效引用。保留仍使用的透明模式等字段，不默认删除历史字库源、改链接布局或换优化选项。用完整相关预览逐像素比较证明外观不变；允许多页变化的测试范围不会自动证明零像素变化。FLASH 看链接器段统计，RAM 静态占用不等于最大栈余量。

执行生成器前检查全部输入和输出路径。旧脚本可能硬编码旧工程目录；不能把“工具存在”理解成适配了新目录。路径修正应指向当前项目，再核对字体、参考素材、字段结构和接口。

字模可能采用二维数组，也可能有只读字节池、偏移表、压缩格式或访问宏。保留当前渲染器支持的接口，不照搬案例的存储形式。需要重新生成时同步维护生成器，避免以后生成覆盖本轮效果。

已有桌面预览可能是实际 C/u8g2，也可能是简化绘图桩。抽取函数和结构桩会随源码演化失效；先确认兼容性和覆盖范围。没有预览工具时可以在当前项目内建立最小的离线渲染，但不能把桩的通过当作板上显示已验证。

默认预览只画一个模式时，必须显式生成所需的另一个模式；内部测试覆盖双通道，不等于展示图片覆盖了双通道。记录实际使用的相关源码、字体和背景资源，部分文件哈希不证明所有旧图仍然有效。

前后比较需要在改动前冻结真实绘图依赖：源码、使用到的头文件、字体、位图和相关算法。仅保存 C 文件、到运行 before 才拷贝资源，会让旧源码搭配新资源；单个源码 SHA 不能证明基线完整。`--report-only` 只整理已有产物，不能代替重新编译绘制。新目录首次快照若来自已经修改的源码，也不代表修改前版本。

并行修改共享源码与检查器时，测试可能采到不同阶段。先核对实际参与渲染的源码、资源与检查合同是否属于同一完成状态，再重跑受影响场景；不要为临时不一致放宽断言。用户反馈失败时先核对实际烧录目录和候选 HEX 哈希，相同哈希可排除这两份文件内容不同，不能证明设备实际已烧录。

按任务选择比较范围：局部页面改动可要求其他页面逐像素一致；统一字体本来会改变多页，改用数据只读、状态恢复、内容完整和布局边界等不变量。已过时的 README、报告文案和检查器常量都需要与当前源码互相核对，不因工具返回成功就照抄旧分页结论。

反色按页面职责选择区域：侧栏、普通右栏、全屏子页分别判断，在内容完成后执行并恢复绘图状态；覆盖普通/选中态和页面往返。静态位图内标题/标语不会被运行时文字记录自动识别，需检查实际像素，替换标题时先处理位图旧文字。更新检查器应依据本次授权布局和真实依赖，不仅移动常量让失败消失；保留越界探针、内容/数据只读与未受影响页面比较。新旧用例集合不同时，报告交集比较及新增覆盖，不能称全部场景都做过前后比较。

专用文字 XBMP 可能超出检查器按普通单字宽高识别的范围；有文字标签和字号日志不等于实际墨迹被跟踪。先确认非空墨迹及合法包围盒，再判断间距；空墨迹的 `-1` 哨兵不能参与并通过碰撞断言。若尚未支持该资源，用资源级像素检查或目视说明限制，不把整套用例通过写成该位图墨迹已自动验证。

真实绘图预览优先替换外设端点，保留字体/UTF-8 解码、位图与几何算法；宿主兼容转换只作用于副本并明确列出。边界观察包括黑字和反白字，并用故意越界的正负坐标样例证明检查器能检出；不能从最终缓冲中的黑点数量推断反白文字无越界。墨迹矩形只证明包围盒关系，自动布局通过仍需查看原生尺寸的可读性。

## 以最少的有效检查交付

- 改动后使用当前工程的真实构建入口，确认明确目标会链接固件，查看编译警告和存储占用。旧案例的 `make all` 或 MSVC 路径只作例子。
- 生成受影响页面的普通值、最长合法值、长状态及有关焦点/模式预览；共享绘图或刷新机制改变时再扩大范围。局部需求不默认重导出和覆盖所有页面。
- 以 1 倍检查可读性，以整数倍最近邻放大检查断笔、粘连、基线与留白；需要时比较更新与完整重绘，确认绘图不改写业务数据。
- 展示本轮实际源码生成的软件预览，说明示例数据和绘图桩限制。使用本轮结果报告验证；历史测试数量、固件大小、照片和日志仅说明当时状态。
- 分别报告编译、桌面回归、烧录和实屏观察。未执行的相关检查写“尚未验证”；编译成功或预览好看不等于真实屏幕已确认。

保留“实际问题、处理方法、用户反馈、验证证据”的案例记录。尚未取得用户实屏反馈时，记录为待确认；不要把生成了一张好看的预览写成用户已认可。
