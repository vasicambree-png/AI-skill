## 页面没切换，先查实际可达性

- `tools/DETAIL_PAGE_FIX.md` 与 `APP/Usart3_task.c::parse_received_frame`：曾有八个活动菜单，但最低参数表仅七项，菜单7被拒绝后旧页继续显示。当前 `min_params[8]` 包含菜单7的两个公共尾参；先校验帧长、参数数、SUM及菜单范围，再写页面/亮屏状态。仅离线设置解析后页面状态不能证明真实帧可进入。
- `APP/yuying_TFT.c::UI_Menu_Display`：全屏路由同时判断等级、菜单及 `re_flag`，防止安装/汇总残留标志抢占返回页。当前绑定也有全屏分支。往返和跨菜单残留标志比单页截图更有诊断价值。
- 同文件 `networking_Control1` 当前仅绘制“开始组网”“返回”，高亮限定0/1；主控的物理按键循环和确认执行不在本仓库。不能据两个按钮就宣称重置/保存动作已被禁用。

## 保存返回是命令行为，不是按钮文案

`tools/BINDING_COLUMNS_SAVE_RETURN.md` 与 `Usart3_task.c` 的 `case 0x05`：有效命令先执行保存并发送结果应答；若当前为三级绑定子页，更新上级页面、焦点与 `re_flag`，立即恢复 DATA 扫描模式并通知息屏策略，随后显示保存结果提示。返回受当前页面条件限定，不能推广为任意页面收到保存命令都跳转。该分支包含保存失败结果，因此不能只按“成功后返回”描述实际行为。

渲染不执行保存；本工程也并非任何情况下都由外部主控独占页面转移。联调需检查主控是否重发旧绑定页覆盖本地返回。一般“保存并返回”参数按钮仍是外部主控业务，不能把上述本地绑定保存路径套到所有设置页。

## 扫描缓存、绑定表、通道与异常容量

`tools/BINDING_ALL_SINGLE_SCREEN.md`、`tools/UNBIND_TWENTY_SINGLE_SCREEN.md` 与 `binding_scan_page` / `binding_device_list_page`：

- 绑定页读 `g_binding_list/g_binding_count`，不再用最近六条扫描名称缓存。候选扫描不等于绑定成功；扫描缓存替换不应改变已绑定清单。
- 正常最多20个不同设备，每台至少占一个测量通道，多路设备减少台数；数组32条不是32个正常独立设备的能力。异常恢复重复记录是防御输入。
- 绑定页正常均衡两列，超过20条采用四列8行兜底，全部保留；解绑页只显示前20条但标题显示真实总数。两页策略不同，不能统一成“都显示全部32条”。当前设备计数已改18px，旧文档14px是先前状态。
- 解绑行含序号、名称和完整12位HEX MAC。实际11px字模非等宽，`D` 可宽9px，最宽MAC108px；按 `ui_text_width` 右对齐，再分配名称余量与6px间隔。正常20台同屏时名称可缩短，这是显式布局取舍，不改写原始名称。
- 覆盖空表、奇偶数量、6/7、10/11、20及异常32条、不同名称/MAC、最宽MAC、按钮焦点和多个旧轮显时刻。当前清单不轮显，旧报告模板提及轮显不能证明源码仍轮显。

## 字体反馈的最终状态与撤回尝试

证据为 `tools/LISHU_WARNING_UI.md`、`tools/generate_menu_assets.py`：

- 曾为14/16px“警”切换宋体 hinting，随后按用户要求撤回。当前 `warning_glyph(args.font, size)` 与正文共用默认微软雅黑粗体；原尺寸单色 hinting 后只向右增强细笔画，基于原始点阵跳过一像素内部字腔，不做竖向膨胀。不是全字库加粗，也不是仍在混用宋体。
- 返回页三组文案当前共用 `return_lishu_glyph` 的 LiSu 22px、4倍栅格、轻微描边与阈值180；早先16/18/20px和原品牌局部增粗已被后续需求替代。参数是本次尝试结果，不是通用默认值。
- 底部专用标语资源同时输出宽/字号/高度宏，绘图和检查同步读取；普通版本居中，最长版本号触发防碰撞左移。三组文案同字体不表示动态版本号也改隶书。
- 黑白资源、同绘图颜色也会因墨点密度显出不同黑度。历史软件预览通过后仍出现用户清晰度反馈；自动边界检查不能证明用户已认可或实屏黑度一致。

## 反色、位图旧字与检查器

`UI_Menu_Display` 在完成内容后局部 XOR：普通菜单仅右栏，全屏绑定/数据子页覆盖整屏，然后恢复颜色、位图模式和字体透明状态。不能全局反相改变首页/侧栏，不能仅核对最终黑点数量就跳过反白文字。

`tools/WEB_UI_ACCEPTANCE_20261008.md` 记录旧检查器标题坐标与网页改动不一致，随后按真实布局修正。静态返回页的旧标题/标语烘焙在位图内，需要清除或重新生成；文字调用日志无法独立识别这类残留。新旧场景数量有增加时只比较共同场景，并独立说明新增检查。

本轮独立审查发现更具体的盲区：`tools/ui_preview/host_render.c` 的 `custom_glyph_active` 仅跟踪宽≤24、高13/16/18/20的单字位图；144×24的专用标语不满足。`ui_preview_text` 无墨迹时输出四个 `-1`，`check_param_pages.py` 的标语右界+4与版本左界比较未先要求有效非空边界。实际历史 `output/warning_weight_20261008/after/draws.tsv` 中 `menu_7` 标语记录为 `CUSTOM_INK ... -1 -1 -1 -1`，能静态确认该断言可能空通过。因此521用例通过不能直接证明专用标语实际墨迹间距已充分自动验证。这里仅记录检查器限制，没有修复来源项目或重新运行其回归。

## 无效字体引用也会占 Flash

`tools/FLASH_OPTIMIZATION.md` 与当前文字调用链：正文经 `ui_text_glyph` 到自定义多字号字模再 `DrawXBMP`，活动绘图已移除无效 `SetFont(UI_FONT_CN)`。历史记录中 map/nm 证明旧字库由该引用保留，移除后 FLASH减少132132字节，309个同集合预览逐像素相同；这些数字不是本轮新测试。

历史字库源码/宏保留由既有链接回收处理；仍使用的透明模式保留。后续新增原生 u8g2 文本需要重新检查字体初始化和占用，不能认为留下宏就已有有效字体上下文。
