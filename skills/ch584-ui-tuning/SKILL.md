# CH584 及类似单色屏 UI 修改

把参考图和实物反馈落实到目标工程的原生像素布局，保留现有数据来源与操作语义。本 skill 跨工程使用；经验和案例都随本 skill 保存，不依赖某个旧项目目录。

## 选取必要的经验

- 修改字体、混排对齐、图标、数值区或复刻布局时，读 [通用 UI 修改经验](references/ui-experience.md)。
- 需要了解真实的历史问题、或修改原初锚力工程时，按需读 [初锚力案例快照](references/chumaoli-case.md)。案例中的路径、分辨率、协议、字号和编号不属于新项目的默认值。
- 涉及绑定后等待数据、混合传感器通道、20 通道列表、真实 C 预览或刷新调度时，按需读 [蓝牙显示案例快照](references/bluetooth-display-case.md)。它记录当前源码与旧说明不一致的具体例子，不规定其他项目必须采用 20 通道同屏。
- 涉及菜单切换不生效、保存返回、扫描/绑定清单、同屏 MAC、局部反色、小字黑度或字库占用时，读 [蓝牙 UI 后续踩坑记录](references/bluetooth-ui-followup.md)。它区分已撤回的尝试、最终源码和历史验证。
- 涉及保存提示后旧页重现、主控按键与显示状态不同步、固定十行双列、无线档位/版本字段或密集字粘连时，读 [蓝牙 UI 状态联动与后续修正](references/bluetooth-ui-state-followup.md)。这是 10 月 10 日复核的后续快照，覆盖旧案例已被替代的布局和格式。
- 涉及上电/复位瞬间画面、品牌图延迟或重复出现、桌面预览代码被 IDE 编入固件时，读 [启动初始化踩坑记录](references/startup-initialization-case.md)。区分 MCU 首次启动与主控请求的运行中重初始化，不能只改一个共用入口就宣称时序正确。

## 确认当前目标

从用户指定目录或当前工作目录查找实际工程入口、显示初始化和绘图调用链。确认芯片/显示库、逻辑分辨率、旋转、颜色极性、数据绑定、资源生成与编译配置；检查已有修改。项目可能含多个版本，按实际参与构建的源文件定位。

在 u8g2 项目使用已有 u8g2；直接 SPI/自定义帧缓冲项目沿用它的绘图层，不为了使用经验引入 u8g2。没有当前工具或测试脚本时，先识别该工程已有验证方法，必要时在当前项目内建立最小的相关预览，不能直接调用案例里的路径。

用户只要求检查或规划时保持只读。已授权修改时，完成必要分析后继续实现和验证，不因 skill 增加固定确认环节。

## 找到真正需要修改的层

| 需求或现象 | 首先检查 |
| --- | --- |
| 固定标签、标题、Logo、装饰线不变 | 静态背景、资源生成器、实际 include 和链接目标 |
| 数字、状态位置或字号不对 | 数据格式化、绘图辅助函数、实际字符串宽度、基线/左上角坐标约定 |
| 小字断笔、发白、各字高低不同 | 字体源、字模阈值、可见边界、字库覆盖与混排规则 |
| 换了 SetFont 却没变化 | 实际文字入口是否改用自定义字模、尺寸参数与资源表 |
| 已绑定但显示无类型，或零值被当成无数据 | 绑定元数据、通道类型映射与接收有效标志的分工 |
| 首次进入正确，更新后残影/焦点错乱 | 清除矩形、旧 XOR 焦点恢复、缓存键、局部更新和完整重绘 |
| BLE 已更新但界面等按键才变化，或频繁收帧时卡顿 | 重画请求来源、请求合并、消费节流、息屏门控与发送阻塞 |
| 预览与实屏黑白相反 | 缓冲位值、绘图颜色、发送反相、控制器极性、导出映射 |
| 菜单存在但进不去，或切换后仍是旧子页 | 帧解析最低参数表、拒绝后的旧状态、页面等级/菜单归属/子页标志的组合路由 |
| 删了按钮但按键仍能选到或执行 | 外部主控的焦点循环、确认分支与命令发送；显示端是否拥有这些逻辑 |
| 保存提示结束又回到旧子页 | 真实 UART 消费顺序、后续页面快照、提示倒计时与页面确认条件；分别排查残留标志和完整旧帧覆盖 |
| 所有无线图标都进入回退档 | 实际发送字段是原始量还是编码档位、发送端取值、解析位置及资源索引映射 |

静态资源改生成器及对应产物，动态内容改当前绘图入口。代码、资源和构建目标三者必须对应；不要只改一张预览图。执行生成器前检查输入和写入路径，确认输出在当前工程且不会覆盖不相关材料。

## 排版和字体决策

- 先分区、分配重要数字与单位的空间，再安排标签和装饰。根据当前类型与协议的最长合法内容检查最终字号，不能只看普通样例。
- 用可见墨迹边界做视觉居中；字符串共用基线，混排数字/汉字比较可见垂直中心。不要强制把所有字符逐字拉成同一宽高。
- 小字按目标尺寸评价笔画与字腔。需要时离线放大栅格化、降采样并调阈值；不默认膨胀一圈或横向压扁文字。
- 同一绘图颜色下的黑度差异先查墨点密度；用户要求同字体时保留字体源，可比较原尺寸单色 hinting 与降采样，局部增强须保留窄字腔。专用位图的宽高、基线和间距同步用于绘图与检查。
- 图标按原生像素检查关键轮廓与间隔，保留用户参考中的要素。动态数字不裁进背景，样例值不写死到设备显示逻辑。
- 颜色、字库、品牌字体和布局随当前需求确定；单次历史选择不成为所有项目的固定风格。

## 保留数据与交互

纯 UI 修改保留当前字段映射、数值换算、协议、通道数据、页面/焦点编号、密码及成功分支、保存/返回流程。参考图的新按钮不自动成为新功能。隐藏某通道不等于清空其数据；不同页面是否隐藏以本工程分支为准。

元数据已知与数值已接收分别判断；类型、名称和单位不必等第一包遥测才出现。零值不能代替接收有效标志，混合设备的各子通道类型按当前解析规则确定。分页或同屏改动只改变授权的展示集合，保留主控页面状态与退出流程。

改变共用常量前搜索所有引用；只调整一个页面时隔离该页布局。移动动态内容时同步核对清除区域与缓存失效条件，恢复绘图颜色、透明模式及临时反相状态。绘图仅呈现外部主控动作时，不添加实际硬件动作。

页面可达性沿协议解析到活动回调表核对，子页路由包含所属菜单，测试切换时残留标志。明确扫描候选、已绑定设备、测量通道和数组容量的区别；设备清单按实际业务数据源展示。按钮文案或隐藏项不代表主控行为已改变；已存在或明确授权的命令层页面转移仍按真实实现保留，检查应答、提示、扫描/息屏策略与主控后续帧。

## 验证与交付

1. 资源有变化时，核对字符覆盖、位图格式、取址接口与生成一致性；备份不进入正式源集合。
2. 有固件改动时，用当前工程实际构建命令和明确目标，确认发生编译/链接、产物对应本轮源码，查看警告和 FLASH/RAM。不要照抄案例的 `make` 或本机工具链位置。
3. 用当前真实绘图代码生成相关预览；绘图桩无法模拟的部分说明限制。检查 1 倍可读性、整数倍像素、普通/极值/长状态，以及与改动有关的页面、焦点和通道模式；预览明确传入模式。涉及数据状态时覆盖等待、真实零值和部分接收；反白文字也要检查实际墨迹及单元格内部碰撞。
4. 检查绘图不改写输入数据、连续刷新没有残影；涉及缓存时比较局部更新与完整重绘，涉及共享代码时核验邻近页面。按范围做相关回归，不默认全量重导出或覆盖所有历史图片。
5. 交付具体文件、原因、软件预览和本轮实际验证结果。源码检查、编译、桌面测试、烧录及实屏观察分别报告；未执行的相关检查标为“尚未验证”。文档更新不需要固件构建或烧录。

只有用户授权安装/修改全局资料时才维护本 skill；普通 UI 任务的源码、资源和验证输出留在当前工程。不要因复用经验自动修改旧工程或全局配置。
