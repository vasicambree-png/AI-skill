# 跨芯片、跨模块适配

此表用于找出需要现场核对的适配项，按任务涉及的模块选用；不是要求每个项目建立全部工具。

| 适配项 | 从哪里确认 | 可复用的做法 |
| --- | --- | --- |
| 芯片/SDK/运行模型 | 工程配置、头文件、启动文件、调度入口 | 沿真实调用路径找诊断位置，沿用当前抽象层 |
| 构建与镜像 | 项目文件、链接脚本、现有构建命令 | 自动构建关联实际输入与生成规则；不误判正常生成 |
| 身份与下载 | 当次枚举、芯片手册/工具能力、探针输出 | 检查与写入绑定同一目标；型号相同不等于同一块板 |
| 程序/配置存储 | 链接与 Flash 布局、实际下载/擦除设置 | 同时核对镜像和擦除范围、需保留区；不照搬地址 |
| 调试口与业务口 | 初始化、引脚配置、回调和实际接线 | 识别逻辑边界与既有复用机制；避免日志破坏业务帧和未经设计的电气并接 |
| 唤醒/电源/执行器 | 电源控制、休眠状态机和板级电路 | 前置状态符合该场景；唤醒/故障测试不强制先进入正常工作状态 |
| 协议与时限 | 帧解析、状态机、周期广播/数据流实现 | 按实际链路模型验收；请求需关联，流/事件需验证更新和输出 |
| IRQ/DMA/队列 | 中断所有者、缓冲和任务间交接 | 观察完整数据路径；队列丢数据后能可靠恢复 |
| 实物可观察量 | 采样点、屏幕、对端、仪器 | 使用与目标行为对应的证据，避免仅靠日志结论 |

模块示例：

- UART/CAN/I²C：依实际协议检查请求/应答、周期流或事件；总线 ACK 只证明相应总线阶段，不证明应用完成。接收恢复使用该协议边界，不固定换行。
- ADC/FFT：触发计数 → 采集完成 → 数据更新 → 分析输出。离线已知输入可验证算法；电压、频率与噪声仍需真实信号和测量。
- 屏幕：命令接收 → 数据更新 → 绘制入口 → 像素观察。启动日志不能替代显示观察。
- BLE/LoRa：按单向广播、遥测或双向请求检查发送、实际接收及数据更新；只在协议存在应答时验收应答。明确本机发送回执与远端业务回执的差别。

本技能源自一个 STM32 底板与 CH584 屏幕工程的离线准备。来源项目曾完成部分离线验证，具体版本和范围查维护库的 `docs/PROVENANCE.md` 与 `docs/VERIFICATION.md`；这些历史记录不证明当前脚本或其他项目已验证。完整实物闭环尚未完成。来源项目的固定引脚、波特率、COM、探针序列号、UID 地址、Flash 容量和具体命令都不属于跨项目默认值。
