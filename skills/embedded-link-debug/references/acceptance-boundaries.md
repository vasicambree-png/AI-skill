# 反例与验收边界

设计自动验收、恢复或烧录方案时，用相关反例检查判据；不要求所有模块引入全部字段或测试。

| 观察或方案 | 为什么不能据此下结论 | 应核对的证据/行动 |
| --- | --- | --- |
| 新请求后收到同命令响应，ok 增加、pending 清零 | 可能是前次超时请求的迟到回复，或主动上报共用完成路径 | 查看匹配和超时/迟到处理；不能排除混淆时，只证明收到有效帧，指定请求完成仍待验 |
| 清空本机 RX 后再发请求 | 旧帧可能仍在对端或传输链路中 | 依据协议匹配或受控实验排除；不把 flush 当作因果保证 |
| pending 变为 0 或串口输出 OK | 超时、错误也能清 pending；OK 可能只表示入队 | 验证生产字段更新位置和结束原因，分开解析、接受、业务完成与新数据 |
| 计数由最大值变为 0 | 回绕和复位可能相同 | 确认字段宽度、同一启动周期和观测上限；不能区分则不判通过 |
| 缺错误字段、日志被截断 | 默认补零会掩盖失败 | 只要求本轮必要字段，但它们必须有效完整；证据不足使用尚未验证 |
| 连续采样或广播没有 READ/pending | 这些链路本来就不需要请求—应答 | 验收触发、更新、速率、连续性和实际输出，保持正常协议 |
| 二进制协议丢字节后等待换行 | 后续合法帧可能没有换行，导致恢复失败 | 按帧头/长度/校验、间隔或其他实际边界重新同步 |
| 有界 ISR 解析改到主循环 | 可能增加响应时延、缓冲和竞态 | 先验证真实时限与调度；不为“统一架构”迁移正常逻辑 |
| 构建正常生成头文件导致前后哈希不同 | 受控生成是构建的一部分，不等于源输入被外部改动 | 记录生成规则及编译消费的实际产物，识别非预期输入变化 |
| 同型号探针目标预检成功 | 写入进程可能默认选择另一只探针/板 | 检查和写入显式绑定同一目标，无法保证则停止写入 |
| HEX 无配置地址，备份长度和哈希正确 | 实际擦除页仍可能覆盖配置；哈希不证明读取正确或可恢复 | 查看真实擦除单元、工具设置、保留区与读取状态；写前解决冲突 |
| 增加 printf 或 HOLD 后故障消失 | 日志/保持改变了时序和唤醒条件 | 对比诊断副作用，释放后复测原触发场景；不直接宣布根因已修复 |
| DMA 回调未出现 | 触发源、输入、电源、IRQ、DMA 状态和观测本身都可能造成缺口 | 沿最早未证实的阶段检查，先用证据区分假设再决定修改位置 |

停止循环的依据是当前目标所需证据满足，而不是“所有日志没有 ERROR”。若同一修改反复无效或结果相互矛盾，停止重复擦写/增加补丁，保留证据并选择新的可区分检查；用户输入或物理操作是唯一缺项时，说明需要的具体信息。

验收判据来自目标行为和已核对的实现。AI 可以修正被证据证明有误的测试，但要解释依据并保留原失败记录；不能为了变绿删除断言、降低目标或修改预期值。每轮记录假设、变更、镜像身份、实验与判定原因，防止把多个不同试验混成一次成功。
